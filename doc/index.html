Lucide icons in your Android app, from one list.

You write the icon names in build.gradle. lifabt downloads the SVGs once, converts them to Android VectorDrawables, and adds them to your app as R.drawable.lucide_*.

In a hurry? 1) gradlew.bat publishToMavenLocal in the plugin folder. 2) Add mavenLocal() to pluginManagement. 3) Add the plugin and an icons list to app/build.gradle. 4) Build, then use @drawable/lucide_camera. Details below.

Overview

Normally you would import each icon by hand through Android Studio’s Vector Asset tool. lifabt does that for a whole list at build time, so the icon list lives in code and is easy to review.

  • Input: icon names from lucide.dev/icons, such as camera or arrow-right.
  • Output: XML drawables like lucide_camera.xml, generated in build/generated/lucide/res/drawable.
  • Works with: XML layouts, Java, Kotlin and Jetpack Compose.

You do not need adb or a phone to generate the icons. You only need a device or emulator when you run the finished app.

1. Install the plugin

The plugin is not on the Gradle Plugin Portal yet, so publish it to your local Maven repository. Do this once per computer, and again after you change the plugin’s code.

cmd, inside the lifabt foldergradlew.bat publishToMavenLocal

Check that the jar contains io/github/tarun922/lifabt/LifabtPlugin.class:

jar tf build\libs\lifabt-0.1.0.jar

If Gradle says “implementation class … was not found in the jar”, the package line in the Java files does not match the folder. All four files must start with package io.github.tarun922.lifabt;.

2. Set up your app

2a. Tell Gradle to look in your local repo

Put mavenLocal() first in the project’s settings.gradle:

settings.gradlepluginManagement {
    repositories {
        mavenLocal()
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}
settings.gradle.ktspluginManagement {
    repositories {
        mavenLocal()
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}

2b. Apply the plugin in the app module

Edit the module’s own file (usually app/build.gradle), not the root one.

app/build.gradleplugins {
    id 'com.android.application'
    id 'io.github.tarun922.lifabt' version '0.1.0'
}

lifabt {
    icons = ['camera', 'arrow-right', 'circle-user', 'settings']
    version = '0.460.0'   // pin the icon set (recommended)
}
app/build.gradle.ktsplugins {
    id("com.android.application")
    id("io.github.tarun922.lifabt") version "0.1.0"
}

lifabt {
    icons.set(listOf("camera", "arrow-right", "circle-user", "settings"))
    version.set("0.460.0")   // pin the icon set (recommended)
}

If your project uses a version catalog (libs.versions.toml), you can still write the plugin id and version directly as above. It does not have to go in the catalog.

3. First build

Press Sync Now in Android Studio and build, or run:

gradlew.bat assembleDebug
gradlew.bat generateLucideIcons   # icons only, no app build

You should see lifabt: downloading camera for each icon, then lifabt: generated 4 icon(s). Two folders appear:

FolderWhat is in it
app/lucide-icons/<version>/The downloaded .svg files. This is the cache. Commit it.
app/build/generated/lucide/res/drawable/The generated XML drawables. Never edit or commit these.

The generated XML is a normal <vector> with a 24×24 viewport, strokeWidth="2", round caps and joins, and a black stroke, the same style as Lucide’s SVGs.

4. Use the icons

The drawable name is the prefix lucide_ plus the icon name with dashes turned into underscores: arrow-right becomes lucide_arrow_right.

<ImageView
    android:layout_width="24dp"
    android:layout_height="24dp"
    android:src="@drawable/lucide_camera"
    android:contentDescription="@string/take_photo"
    app:tint="?attr/colorOnSurface" />

<!-- Material button with an icon -->
<com.google.android.material.button.MaterialButton
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Next"
    app:icon="@drawable/lucide_arrow_right" />
Icon(
    painter = painterResource(R.drawable.lucide_camera),
    contentDescription = "Take photo",
    modifier = Modifier.size(24.dp)
)

IconButton(onClick = { /* … */ }) {
    Icon(painterResource(R.drawable.lucide_settings), contentDescription = "Settings")
}
binding.icon.setImageResource(R.drawable.lucide_camera)
imageView.setImageResource(R.drawable.lucide_camera);

Always give icons a contentDescription when they act as buttons, so screen readers can announce them. Use null for purely decorative ones.

Recipes

Menus and bottom navigation

Menu items take the icon directly. BottomNavigationView and Toolbar tint it for you.

res/menu/bottom_nav.xml<menu xmlns:android="http://schemas.android.com/apk/res/android">
    <item android:id="@+id/nav_home" android:title="Home"
        android:icon="@drawable/lucide_house" />
    <item android:id="@+id/nav_settings" android:title="Settings"
        android:icon="@drawable/lucide_settings" />
</menu>

Lucide sometimes renames icons (for example home became house). If a name fails with “not found”, search lucide.dev for the current one, or pin an older version.

Icon inside a TextView

<TextView
    android:text="Camera"
    android:drawableStart="@drawable/lucide_camera"
    android:drawablePadding="8dp"
    android:drawableTint="?attr/colorOnSurface" />  <!-- API 23+ -->

One reusable Compose wrapper

Keeps size and colour consistent across the app.

@Composable
fun LucideIcon(
    @DrawableRes id: Int,
    contentDescription: String?,
    modifier: Modifier = Modifier,
    tint: Color = LocalContentColor.current
) {
    Icon(painterResource(id), contentDescription, modifier.size(24.dp), tint)
}

// usage
LucideIcon(R.drawable.lucide_camera, "Take photo")

Choosing an icon by name at runtime

Only do this if the icon name comes from data. Prefer direct R.drawable references.

val id = resources.getIdentifier("lucide_$name", "drawable", packageName)

Release builds with resource shrinking remove drawables that no code references directly. Protect the icons by adding this file:

app/src/main/res/raw/keep.xml<resources xmlns:tools="http://schemas.android.com/tools"
    tools:keep="@drawable/lucide_*" />

Moving from Vector Asset imports

Delete the hand-imported Lucide XML files, add the names to icons, and use prefix = 'ic_' if your existing code already uses ic_ names. Anything with the same file name in src/main/res will clash with the generated one, so remove the old copies.

Configuration

OptionDefaultWhat it does
iconsnone (required)List of Lucide icon names, exactly as on lucide.dev. Lowercase letters, digits and dashes only.
version"latest"The lucide-static version on npm. Pin it so every machine gets identical icons.
prefix"lucide_"Start of every drawable name. Must match [a-z][a-z0-9_]*.

Example with a custom prefix: prefix = 'ic_' makes R.drawable.ic_camera.

Colour & size

The generated icons have a fixed black stroke and no fill. Colour them with a tint, not by editing the XML.

  • XML: app:tint="?attr/colorOnSurface" on an ImageView. Using a theme attribute means dark mode works automatically.
  • Compose: Icon uses the current content colour by default. Pass tint = MaterialTheme.colorScheme.primary to change it.
  • Size: the icons are 24dp but scale cleanly. Set any layout_width and layout_height, or Modifier.size(…).
  • Thicker or thinner lines: not configurable in 0.1.0. All icons use stroke width 2.

Git, CI & offline builds

Commit the cache folder. Then nobody, including your CI server, needs internet to build.

.gitignorebuild/
.gradle/
local.properties
# do NOT ignore app/lucide-icons/
  • With version = 'latest', the committed cache is what keeps builds stable. Without a cache, a newer Lucide release could change an icon between two builds.
  • Pinning version and committing lucide-icons/ together is the safest setup.
  • Do not commit build/generated/lucide/. It is recreated on every build.

Daily workflow

Add an icon: find its name on lucide.dev, add it to icons, sync. Only the new SVG is downloaded.

Remove an icon: delete it from the list. The generated folder is cleared on each run, so the old drawable disappears. Any code that still uses it fails to compile, which tells you where to clean up.

Update the icon set: change version to a newer one. It gets its own cache folder (lucide-icons/<version>/), so you can compare the two before deleting the old one.

Rename the prefix: change prefix, then update every R.drawable reference.

Regenerate by hand: gradlew.bat generateLucideIcons.

Multi-module apps

Apply the plugin in the module that owns the icons. A shared :ui or :core library module works well, using com.android.library. Other modules then reach the drawables through that module’s R class, or through the app’s merged R if the app depends on it. With non-transitive R classes (the default in new projects), import it like com.yourapp.ui.R.

CI & sharing the plugin

Because the plugin lives in your local Maven cache, a fresh machine does not have it. You have three options.

OptionGood for
Publish on each machineSolo work. Run gradlew.bat publishToMavenLocal once.
Build it in CI firstTeams with a CI server. Example below.
Composite buildKeeping the plugin folder next to the app. In pluginManagement write includeBuild("../lifabt"), then apply id 'io.github.tarun922.lifabt' without a version. This is a standard Gradle feature, but I have not tested it with this plugin.

  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/checkout@v4
        with:
          repository: YOUR_GITHUB_NAME/lifabt
          path: lifabt
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: 17 }

      - run: chmod +x gradlew && ./gradlew assembleDebug

With lucide-icons/ committed, this build needs no icon downloads. For wider use, publish the plugin to the Gradle Plugin Portal or a private Maven repository and remove mavenLocal().

How it works

  1. The plugin registers a task called generateLucideIcons that runs before preBuild.
  2. For each name, it looks for lucide-icons/<version>/<name>.svg. If missing, it downloads it from cdn.jsdelivr.net/npm/lucide-static@<version>/icons/<name>.svg.
  3. It converts the SVG elements (path, line, polyline, polygon, circle, ellipse, rect, g) into VectorDrawable paths.
  4. It writes build/generated/lucide/res/drawable/<prefix><name>.xml and adds that res folder to the app’s main source set.

Test without a phone

The conversion needs no Android SDK. Make a tiny test project containing only the plugin:

settings.gradlepluginManagement { repositories { mavenLocal(); gradlePluginPortal() } }
rootProject.name = 'lifabt-test'

build.gradleplugins { id 'io.github.tarun922.lifabt' version '0.1.0' }
lifabt { icons = ['camera', 'arrow-right'] }
gradle generateLucideIcons
dir build\generated\lucide\res\drawable

Good result: one .xml per icon, each starting with <vector. Then switch the internet off and run gradle generateLucideIcons --rerun. It should succeed from the cache without printing “downloading”. A wrong name such as abcxyz should fail with a clear “not found” message.

This checks the downloader and converter. The automatic res registration only runs inside a real Android project, so build one real app once to confirm it.

Troubleshooting

ProblemFix
Plugin … was not foundRun gradlew.bat publishToMavenLocal and make sure mavenLocal() is inside pluginManagement.repositories.
implementation class … not found in the jarPackage names in the Java files must equal io.github.tarun922.lifabt. Rebuild with clean publishToMavenLocal. If an old copy is cached, delete %USERPROFILE%\.m2\repository\io\github\tarun922 and publish again.
R.drawable.lucide_x is unresolvedCheck the icon is in icons and the build ran. If the log says could not auto-register the res folder, add sourceSets.main.res.srcDir("build/generated/lucide/res") inside android { }.
Wrong module in Android StudioThe plugin must be in app/build.gradle, not the root build.gradle.
Download of 'x' failed / no cached copyConnect to the internet once, or place x.svg by hand in lucide-icons/<version>/.
Icon 'x' not foundCheck the spelling on lucide.dev. Some icons were renamed between versions, so check the version too.
Icon is black on a dark backgroundAdd a tint (Colour & size).
Deprecation warning about Gradle 10Run with --warning-mode all to see whether the plugin or your own scripts cause it. The build still works.
'.' is not recognized on WindowsIn cmd, use gradlew.bat. The ./gradlew form works in PowerShell, Git Bash and Linux or macOS terminals.

FAQ

Does it make my APK bigger?

Only by the icons you list. Each generated XML is roughly 0.5–1.5 KB.

Which Android versions work?

VectorDrawable is built in from API 21. For older versions you need the AndroidX vector support setup in your app. Most new projects use minSdk 21 or higher, so nothing extra is needed.

Can I fill an icon instead of outlining it?

Not in 0.1.0. Lucide icons are stroke-only and the plugin keeps them that way.

Can I use icons from another library?

No. The plugin downloads only from lucide-static.

Do I need internet on every build?

No. Only for an icon that is not yet in lucide-icons/.

Can I edit a generated XML?

You can, but the next build overwrites it, because the folder is cleared on each run. Copy the file into src/main/res/drawable under a different name if you want a custom version.

Does it work in Flutter, React Native or Qt?

No. It targets native Android projects with Gradle.

Limits & license

  • Only the SVG elements listed above are converted. This covers all Lucide icons.
  • Stroke colour (black) and width (2) are fixed in this version.
  • The plugin is published to the local Maven cache only, so every developer or CI machine must run publishToMavenLocal once, or host the plugin in a shared Maven repository.
  • License: the plugin’s own code is under the license in its LICENSE file (GPL v3 in the current zip). Lucide icons are a separate project under the ISC license. They are downloaded at build time, so check lucide.dev/license before you ship.
